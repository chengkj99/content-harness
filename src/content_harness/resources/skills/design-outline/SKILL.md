# design-outline

输入：已批准 brief、style-spec。
1. 以 brief 的读者问题为主线，按段落说明这一节解决什么、凭什么、读者得到什么。
2. 使用 Scene 层结构规则：需要具体开头时，从已有来源或真实经历中选择；不得为了张力补造事件。
3. 为每节标注对应主张与边界，结尾兑现 brief 的 action。必要时指出材料缺口并退回 research-claims。
输出：outline。完成标准：覆盖 brief 的核心判断，章节不偏题，每个需要事实支持的段落都有已登记主张。

操作前读取 [资产与 CLI 契约](../content-harness/references/contract.md)。

遇到缺少输入、stale 依赖或人类审批要求时，报告阻塞及具体下一步。Agent 不得自行执行 approve、confirm-author、verify-claim、style-promote、style-rollback。
