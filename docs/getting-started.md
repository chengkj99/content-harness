# 新手上手指南：和 AI 一起完成第一篇文章

你不需要会编程。使用时，你主要向 AI 说明需求、提供资料、审阅文章；AI 负责保存文件和调用工具。重要确认可以直接在 Agent 聊天窗口完成：先看内容，再明确回复确认对象。首次安装仍需要准备本地工具。

## 先认识三个东西

| 名称 | 可以怎样理解 |
|---|---|
| AI 客户端 | 你与 AI 对话的应用，需要能操作电脑上的项目文件并运行命令 |
| Content Harness | 给 AI 用的写作流程和工具，帮你保存过程、检查遗漏、继续改稿 |
| 写作项目 | 你在电脑上选定的一个文件夹，素材和文章都围绕它组织 |

Skills 是给 AI 看的操作指引，你不用逐个阅读。后文的提示词和确认回复都发在聊天框里。Agent 会读取当前版本并记录你的明确确认；版本变化时会请你重新审阅。

当前安装支持 macOS / Linux。Windows 没有完成支持与验证，不建议照抄命令尝试原生运行。Codex、Claude Code、Cursor 提供了安装目录支持，但实际客户端是否发现 Skills、是否拥有文件和命令权限，需要在第一次准备时检查。

## 第一次准备

### 1. 选择一个写作文件夹

例如在文件管理器里创建“我的写作”，然后在 AI 客户端里打开这个文件夹。已有 LLM Wiki 的用户可以直接打开自己的知识库根目录。不需要为了使用工具重新组织整个知识库。

发给 AI：

```text
我想用 Content Harness 写文章，但不懂命令行。
请先确认你能读取当前项目文件、执行本地命令，并使用 Agent Skills。
项目地址：https://github.com/chengkj99/content-harness

先检查是否已经安装 Content Harness、uv 和可用的 Python 3.11 以上版本。
若需要安装，请解释要安装什么，并按当前客户端的权限规则操作。
安装本项目的 Skills；如果已有安装且内容不同，先说明并保留旧文件。
检查工具和 Skills 是否可用，告诉我通过了哪些检查。
如果你只能聊天、无法操作文件，请直接告诉我，不要声称已安装。
```

uv 是安装和运行 Python 工具的小程序。通常由 AI 帮你检查和安装；如果需要你亲自操作，可参考 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/)。Content Harness 从 GitHub 安装，不是从一个同名网页服务注册。

准备成功时，AI 应能展示工具版本、当前项目路径和 Skills 安装位置。如果它说“工具不存在”或“权限不足”，先完成环境问题，再开始写作。

### 2. 告诉 AI 素材和成品的位置

发给 AI，按你的情况替换引号中的内容：

```text
把当前文件夹作为我的写作项目。
素材从“素材”和“笔记”读取，已有文章在“旧稿”中，请用它检查选题重复。
新文章保存到“成品文章”，每篇单独建一个文件夹。
以后也默认使用这些位置。保留所有已有文件，不移动旧文章。
请用 Content Harness 初始化或调整配置，完成后用中文复述实际目录。
如果这些文件夹不存在，先告诉我；如果已有配置，优先沿用并只改我指定的部分。
```

没有资料也可以告诉 AI“这次只从我在聊天里提供的想法开始”。已有 Wiki 可以说“资料在原始资料/读书笔记，成品放到知识库/我的文章”。工具支持项目内的中文路径和空格；具体见 [目录设置](wiki-integration.md)。

初始化只做准备，不会自动生成文章。旧项目更新配置不会搬走旧文件。

### 3. 填写一次作者说明

发给 AI：

```text
请帮我整理作者说明，保存在当前项目的作者资料文件中：
我的目标读者是：希望改善工作习惯的普通上班族。
我的表达偏好是：具体、清楚，像和同行交流，少用口号。
可以使用的个人经历：暂时没有。没有我的明确材料，不写“我亲测”或“读者反馈”。
不希望出现的表达：制造焦虑、夸大收益、为了像真人而编故事。

只根据我提供的内容整理。整理好后在聊天中展示给我审阅，等我明确确认。
```

你检查资料后，在聊天中回复“我确认这份作者说明”。Agent 会记录对当前版本的确认。以后作者资料改变，需要重新确认。

## 从一个想法到一篇文章

下面用同一个题目演示。每段提示词都可以直接发给 AI；不需要一次把所有步骤发完。

### 第一步：先确定这篇文章要解决什么问题

```text
使用 Content Harness，开始一篇新文章。
主题：为什么收藏了很多资料，做事时还是不知道下一步？
场景：工作方法，使用 work-habits 作为这类文章的风格记忆分组。
读者：想改善工作习惯，但不想学习复杂方法的普通上班族。
目标：读完后能选一个手头任务，把一条资料变成一个具体行动。
篇幅：大约 1200～1800 字，按内容需要调整，不为凑字数添加空话。
材料：优先使用项目已配置的资料目录，需要外部事实时查找原始来源。
边界：不虚构作者经历，不编造效率提升的数据，不把有限经验说成普遍规律。

先检查是否与旧稿重复，整理依据，再给我一份简短的写作方向说明。
说明读者、核心观点、文章不讨论什么、还缺哪些材料。
先做到方向确认，等我看过再写全文。
```

你会得到“写作方向说明”，工具内部叫 brief。AI 还会给文章生成一个编号，例如 `2026-09-09-material-to-action`。这个编号用于找到文章，**不是文章标题，也不是你需要背下来的命令**。

如果方向不对，直接说：

```text
这次只讨论“知道很多但不知道从哪一步开始”，不扩展到所有学习问题。
核心观点改成：先围绕一个真实任务选择资料，再写一个可检查的下一步。
请修改方向说明，重新给我审阅。
```

方向满意后，在聊天中回复“我确认这篇文章的写作方向，请继续”。Agent 会把这次确认绑定到你审阅的版本，然后继续写作。若方向已经修改，Agent 会展示新版请你重新确认。

### 第二步：按需选择表达风格

默认风格已经可用，以下三种任选一种。

正常表达：

```text
这篇按正常、清楚的方式写，不额外强化传播风格，也不用刻意口语化。
请先给我提纲，再根据已经确认的方向、提纲、事实依据和表达要求写正文。
```

公众号高传播表达：

```text
这篇选择公众号高传播风格，中等强度。
开头用具体问题，标题讲清内容，每一节都让读者获得一个明确收获。
不要制造焦虑，不做正文无法兑现的承诺，不改变已有事实的范围。
请把风格应用到提纲和正文，再继续。
```

高传播加去 AI 味：

```text
采用公众号高传播风格，中等强度；正文完成后再做一轮去 AI 味。
删掉空泛排比、机械总结和没有信息的过渡句，保留我原本的表达习惯。
数字、引用、限定词和已确认经历不能因为润色发生变化。
```

“去 AI 味”是编辑要求，不是保证通过某个 AI 检测器。“高传播”也是表达策略，不是阅读量承诺。

### 第三步：审阅正文并提出修改

```text
请给我看完整成稿，并用中文说明：
哪些地方依据外部来源，哪些是观点或建议，还有哪些不确定之处。
不要只给我文件路径；先展示便于阅读的正文，同时告诉我文件保存在哪里。
```

需要修改时尽量指出位置和目的，例如：

```text
第二部分太抽象。请保留核心观点，补一个普通工作任务的示例。
示例明确写成假设场景，不能说成我的亲身经历。
结尾只留一个今天就能做的动作。
修改后重新进行受影响的事实和表达检查。
```

你也可以自己打开正文文件修改，再告诉 AI“我手工改过成稿，请先读取最新文件，保留我的修改后继续”。AI 应检测哪些旧检查已经失效，不应该拿旧稿覆盖你。

### 第四步：检查事实，决定是否需要图

```text
请对当前成稿做事实与编辑检查。
逐条判断引用是否真的支持正文，检查有没有遗漏的事实断言、夸大的限定词或虚构经历。
有问题先告诉我位置、原因和修正建议，再处理。
只有在图比文字更容易理解时才配图；不需要图就说明原因。
需要图时保存本地图片，并核对来源、可使用条件和图中文字。
```

如果文章涉及高风险事实，或者 AI 需要把某段内容认定为你的亲历，它会另外请你核验。你可以补材料、删掉断言或收窄范围，不必为了走完流程而勉强确认。

### 第五步：拿到成品

```text
完成检查后，请准备正文、候选标题、摘要、来源记录和必要配图。
给我看最终内容，并告诉我将保存到哪个目录。
准备好后展示最终稿、标题、摘要和配图，等我在聊天中明确确认。
我确认后，导出到项目配置的成品目录，并告诉我从哪个文件开始阅读。
```

你审阅并在聊天中明确确认最终稿后，Agent 会记录确认并导出。这里的 publish 是沿用的命令名称，**确认和导出都不会自动把文章发到公众号或网站**。

最终打开 `article.md` 看正文，`titles.txt` 选标题，`summary.txt` 看摘要，配图在 assets 文件夹中。Markdown 就是带少量排版标记的文本；可以用支持 Markdown 的笔记工具打开。导出成功不等于已适配目标平台，你仍需在发布平台检查排版。

## 写到一半退出了，怎么办

在同一个写作项目里打开 AI，发给它：

```text
使用 Content Harness，继续上次那篇“收藏资料与下一步行动”的文章。
请从磁盘读取最新任务状态，先告诉我做到哪一步、有没有手工修改、接下来需要我做什么。
如果有多个相近任务，请先列出供我选择。保留现有稿件，不重新创建一篇。
```

## 怎样让工具越来越符合自己的习惯

如果只是本篇临时调整，说“这次改短一点，不要记为长期偏好”。如果希望形成长期规则，可以说：

```text
我刚手动修改了成稿的结尾，希望当前文章所在的“工作方法”场景以后都给出一个具体行动，不用泛泛号召。
请先保存修改前后的差异，再检查手改稿。
根据差异提出候选风格规则，给出应该改和不应该改的例子。
展示证据与适用场景，等我确认后再保存为长期偏好，不要自动应用到其他类型文章。
```

AI 会准备候选，而不是立即“学会”。你审阅后在聊天中明确确认该候选，Agent 才会将它写入长期记忆。第一次只要把文章写完即可，这项功能可以以后再用。

## 想换目录或切换内容场景

```text
以后把成品保存到“知识库/专题文章”，旧稿不移动。
下一篇属于“产品解读”场景，请为它设置独立的风格记忆，不复用工作方法文章的特殊表达规则。
先展示你将修改的配置，按我已经说明的位置完成设置。
```

场景名在命令中用简短英文编号，例如 book-notes、product-notes；让 AI 帮你命名即可。场景是偏好分组，不代表软件新增了另一种平台发布能力。

命令看不懂时，随时对 AI 说“解释这条命令会改什么，给我填好实际编号，不要让我猜参数”。[命令白话手册](commands.md)逐条解释了状态、继续、风格、安装，以及哪些命令仅供开发者使用。
